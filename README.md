# 机器人与仿真资产库

本仓库集中保存机器人及仿真资产。按资产用途分类，同一资产的不同格式和平台适配文件放在同一个资产目录中。

## 分类目录

| 目录 | 保存内容 | 分类边界 |
| --- | --- | --- |
| `robots/` | 完整机器人、机械臂、移动底盘、机器人专用部件 | 仅供某个机器人使用的网格、材质、配置随机器人保存 |
| `scenes/` | 仿真世界、房间、道路、地形及场景布局 | 场景引用可复用物体；仅供该场景使用的资源随场景保存 |
| `objects/` | 工具、家具、工件、障碍物、夹爪等独立物体或可复用部件 | 能独立使用且不属于其他专门分类的实体资产 |
| `sensors/` | 可独立复用的相机、雷达、IMU 等传感器资产 | 机器人专用的传感器安装配置仍随机器人保存 |
| `materials/` | 可跨资产复用的材质、纹理及环境贴图 | 单个资产专用的材质、纹理不拆出 |
| `motions/` | 动作、轨迹、动画及运动捕捉数据 | 记录适用机器人或骨架；控制程序不归入本类 |

## 分类原则

1. **按主要用途确定唯一归属。** 完整机器人归 `robots/`，包含机器人的完整环境归 `scenes/`；不因文件扩展名改变分类。
2. **专用资源随资产保存，共用资源独立保存。** 只有确实需要跨资产复用时才拆出，避免过早拆分。
3. **同一资产只保留一个主目录。** URDF、MJCF、USD、SDF、GLB 等格式及平台适配文件放在该目录内，不按格式或仿真器复制整项资产。
4. **跨资产依赖明确记录。** 使用仓库相对路径，并在资产说明中列出依赖；不使用本机绝对路径。
5. **不设长期杂项目录。** 无法归类的资产先判断主要用途；确有新类型时，先更新本分类表再新增顶层目录。

## 命名与组织

资产路径：`<分类>/<资产名>/`。

- 目录和文件优先使用小写英文、数字和短横线，例如 `robots/unitree-go2/`、`scenes/warehouse-small/`。
- 同类重名时添加厂商、型号或用途，不使用 `new`、`final`、`copy` 等含义不明确的后缀。
- 第三方原始资源中被内部引用的文件名保持不变，避免破坏引用。
- 使用 Git 管理修改历史，不创建 `v1/`、`v2/` 或备份副本；确属不同型号的资产分别命名。
- 按需在资产内建立 `meshes/`、`textures/`、`formats/`、`configs/`、`previews/` 等子目录，不要求创建空目录。
- 平台专用内容可放入 `formats/<格式或平台>/`；已有第三方包的相对目录结构优先保留。

## 入库要求

每项资产必须包含自己的 `README.md`，至少记录：

| 字段 | 要求 |
| --- | --- |
| 名称与用途 | 资产是什么，适用哪些场景 |
| 来源 | 原始链接、作者或制作方；自制资产注明自制 |
| 许可 | 许可证名称及许可证文件位置；许可不明时明确标注“待确认，不得再分发” |
| 格式与入口 | 提供的格式、主入口文件及加载方式 |
| 兼容性 | 已验证的平台与版本；未验证的明确注明 |
| 单位与坐标 | 长度单位、坐标轴方向、左右手系；不适用时说明 |
| 依赖 | 仓库内相对路径或外部依赖及版本；无依赖时注明 |
| 验证状态 | 实际执行的加载或检查结果，以及已知限制 |

入库前检查：

- 分类正确，仓库中没有同一资产的重复主目录。
- 保留原作者署名和许可证，确认存储及分发权限。
- 入口文件引用的网格、纹理、配置齐全，无本机绝对路径。
- 至少在目标工具中实际加载一次；无法验证时明确记录，不声称兼容。
- 不提交缓存、临时文件、构建产物、凭据或本地环境。
- 大型二进制文件入库前评估 Git LFS 或外部存储；采用外部存储时记录下载地址、版本与校验值。

本仓库不预设统一仿真平台，也未启用 Git LFS 或自动检查；各项资产的依赖和验证状态见其说明。
